Sudoku and Zebra: four separate ablations

mdm                  Original author-aligned baseline.
mdm_np               Original baseline + two linear neighbor heads.
trajectory_attention Three states + extra attention; no history is read.
trajectory_recurrent The matched attention model + shifted recurrent KV.

Comparisons:
  mdm_np vs mdm
  trajectory_recurrent vs trajectory_attention

Three-state training:
  Mask ratios execute in order t+k -> t -> t-k.
  One ranking gives nested masks. Reveals use correct teacher tokens.
  Weights are [0.25, 1.00, 0.25], divided by 1.50.
  k is sampled in [0.025, 0.10]. Center t is sampled inside valid bounds.
  Counts are rounded and constrained to three strictly decreasing positive
  values. The first state retains at least one revealed eligible token.
  Requested and realized mask ratios are both recorded.
  Sudoku preserves the author's solution-loss mask.
  Zebra preserves the author's all-valid-token training policy.

Memory:
  Extra attention precedes each unchanged author transformer block.
  Both matched models have identical extra parameters, gates and attention
  tensor shapes. History slots exist in both arms.
  The attention control masks every history slot before softmax.
  RM reads previous-pass KV written from the completed corresponding depth.
  Nonfinal writers reuse the next extra-attention entry projection.
  The final depth has a separate KV writer, retained in both models.
  RoPE has token-position and previous/current-age coordinates 0/1;
  64-dimensional heads use a 48/16 spatial/temporal split.
  There is no final-hidden input feedback.
  Each recurrent loss has exactly one backward transition. Cache-input
  leaves and explicit frozen cotangents prevent two-hop backbone credit.
  Compiled backward buffer donation is disabled in both trajectory arms.

Source dropout:
  At the second and third states, masked queries use joint (75%),
  previous-only (20%) or current-only (5%) extra-attention sources after warmup.
  Previous-only probability ramps over 1,000 optimizer steps.
  Both arms use the same source-policy draws. A previous-only control query
  has no available extra-attention source, so its extra residual is zero.
  Ordinary author attention and current input remain active.
  Validation and generation turn off source dropout.
  Identity supervision is disabled by the user's decision: exactly three
  supervised training forwards, with no shuffled-memory reference pass.

Evaluation:
  Normal val/nll keeps the author's single-canvas, no-history ELBO monitor.
  Separate val/trajectory_objective and three masked-token accuracy metrics
  measure the shared three-state evaluation. They are conditional diagnostics,
  not additional likelihood bounds. Validation diagnostics preserve RNG.
  Full generation uses the original author sampler and its candidate policy.
  Memory is stored in original position order and reindexed when the sampler
  moves physical token slots. It resets at the start/end of each generation.
  Completed-puzzle generation accuracy is the main quality comparison for RM.

Scope:
  The author source tree and previous Sudoku/Zebra runs are unchanged.
  No benchmark training was launched. NP+RM merging is deferred until the
  separate ablations support it. The next merged study also needs a
  trajectory+attention+NP control to separate NP gain from recurrence gain.

Working formulation:
  "Neighbor prediction and connected recurrence provide spatial and temporal
  routes for supervising predictive context representations."
  This is the proposed design interpretation; new performance results are pending.

New four-GPU server:
  git clone git@github.com:liuzihau/dc-test.git
  cd dc-test
  conda create -n dcache python=3.9 -y
  conda activate dcache
  bash puzzle_recurrence/setup_server.sh
  bash puzzle_recurrence/transfer_data.sh USER@SOURCE_HOST
  python -m puzzle_recurrence.run_pair --tasks sudoku zebra --dry-run
  python -m puzzle_recurrence.run_pair --tasks sudoku zebra --evaluate

The pair runner uses GPUs0,1 for trajectory_attention and GPUs2,3 for
trajectory_recurrent. It waits for both Sudoku arms before starting Zebra. --evaluate also runs
the final completed-puzzle generation evaluations in separate evaluation folders.
Use --tasks sudoku or --tasks zebra for one dataset only.
Use --attention-gpus 0,1 --recurrent-gpus 2,3 to choose other disjoint pairs.
Logs: outputs/TASK/three-state-ablation/trajectory_attention.log and
      outputs/TASK/three-state-ablation/trajectory_recurrent.log.
Run in tmux or screen to survive terminal disconnection. Add --resume after
an interruption; an existing output folder requires its latest checkpoint.
Generation evaluates 1,280 puzzles every three epochs, plus the final epoch.
Sudoku: 3,6,9,12,15,18,20. Zebra: 3,6,...,39,40.
The same puzzle, row and cell accuracies as MDM/MDM-NP are saved in
generation_history.csv, with each generation's samples and complete.json.
The standard author validation and three-state token metrics remain separate.
Transfer also copies the prepared author caches, avoiding concurrent cache creation
on the new server. Raw data, caches, model checkpoints, and generated results are
excluded from Git.

Double the microbatch without changing effective batch:
  Let the existing queue save an epoch checkpoint, then stop it with Ctrl+C.
  git pull --ff-only
  python -m puzzle_recurrence.run_pair --tasks sudoku zebra --resume --microbatch 64 --allow-microbatch-change
  Global batch512 stays fixed: per-GPU microbatch32->64, accumulation8->4.
  Model, optimizer, EMA, scheduler, sampler cursor and RNG are restored.
  Subsequent corruption grouping differs; this is not bitwise replay of the
  old microbatch run. A batch-change receipt records the transition.
  Full-size batch64 forward/backward checks passed on RTX3090; Zebra RM used
  about21GiB before optimizer/DDP overhead. Smaller GPUs may need batch32.

Old queues had final-only evaluation and kept only recent checkpoints.
Missing older three-epoch checkpoints cannot produce retrospective metrics.
The updated queue records only exact checkpoint epochs; later checkpoints
are never substituted for an earlier epoch's accuracy.
